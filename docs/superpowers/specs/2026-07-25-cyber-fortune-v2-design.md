# 赛博财神庙 v2 —— AI 互动求签固件重设计

日期：2026-07-25
状态：已确认（用户批准）
硬件：Tuya T5AI-Board + 3.5" ILI9488 LCD（GT1151 触摸）+ EM5820H USB 热敏打印机
代码位置：`t5-dev/TuyaOpen/apps/cyber_fortune`（重构现有 app）

## 概要

将现有"离线随机抽 60 支固定签"的单机固件，升级为"像素风动画 + 触屏问答 + 后端
LLM 生成个性化签文"的互动求签机。屏幕**横屏 480×320**，白底黑像素风格，联网调用
专用后端（core-engine，47.98.99.199:8000）生成签文，断网无缝切本地兜底签谱，
小票按需打印。

## 硬性约束

- **横屏**：UI 分辨率 480×320（现固件为竖屏 320×480，显示/触摸都需旋转 90°）。
- 视觉风格：白底 `#FFFFFF`、黑像素 `#000000`、8px 笔触边框；按钮按下反色；
  仅签级徽章允许红色点缀（呼应签筒 GIF 的红色）。
- 签文内容为 AI 原创白话，不使用成语典故故事。
- 交互为混合模式：触屏选类别 + 1 轮预写追问选择题；语音留二期。

## 场景状态机

```
[开机] WiFi 连接 + USB host 上电 + 打印机 worker 初始化
   │  开机首屏：opening_1（彩色版，缩放后）停留约 3s
   ▼
┌─ 待机页 ◀─────────────────────────────────────┐
│  opening_2~6.gif 随机轮播；底部提示"轻触屏幕 求一签"；    │
│  角落像素 WiFi 图标示意在线状态                        │
└── 点击任意处 ──▶ 类别页                              │
      吉祥物问"想问点什么？"                             │
      6 宫格：财运 / 事业 / 姻缘 / 学业 / 健康 / 今日运势   │
      30s 无操作 ────────────────────────────────────┘
      点类别 ──▶ 追问页
            本地题库按类别随机抽 1 题（3~4 个选项）
            点选项 ──▶ 思考/摇签页（两件事并行）
                  ├─ 立刻 POST 后端（10s 超时 → 本地兜底）
                  └─ thinking.gif（保底 2s）
                     → getting_lottery.gif（摇签）
                     → lottery_get.gif（出签）
            签文就绪且动画播完 ──▶ 结果页
                  签级徽章 + 原创白话诗(四句) + 针对性解签 + 行动建议
                  按钮：[打印签文] [再求一签]
                  打印后按钮变"已出票"防连点
                  60s 无操作 → 回待机
```

关键机制：**网络请求与摇签动画并行**。动画序列本身是等待遮罩——网络快时用户
零感知等待，慢时动画自然撑满 10s 超时窗口；超时或报错后无缝切兜底签文，
动画流程不变，用户无感知。

## UI 规范

- 中文字体：开源像素字体 **Fusion Pixel（缝合像素，12px 网格）**，
  ×2 渲染 24px 正文、×3 渲染 36px 标题，与 GIF 线条风格统一。
- **动态汉字覆盖**（关键技术点，三层保险）：
  1. LCD 字库按 GB2312 一级字库（3755 常用字 + ASCII + 标点）生成 LVGL 1bpp
     字体，两个字号合计约 500KB flash；
  2. 打印机 Unicode→GBK 映射表扩到 GB2312 全量（约 35KB）；
  3. 后端 prompt 约束"只用常用字"，服务端再把落在字库外的生僻字替换为常用同义字。

| 文件 | 用途 | 处理 |

- 解码画布约 300KB 放 PSRAM（充裕）；素材压完预计 ~2MB flash，实现阶段核实
  app 分区余量，超限则降帧率或删减 opening 变体。

### GIF 播放编排（已确认）

实测节拍：opening_1 = 3帧/0.6s；opening_2~6 = 各10帧/4.0s；thinking = 10帧/4.0s；
getting_lottery = 4帧/1.2s；lottery_get = 9帧/1.8s。

核心原则：**等待弹性全部吃在 thinking 段；摇签→出签为固定节奏收尾，
每次求签的高潮节拍恒定，不受网络抖动影响。**

```
开机     opening_1 循环 5 遍（3s，后台并行连 WiFi / 起 USB host）→ 待机
待机     opening_2~6 洗牌轮播：随机排列 5 支各播一遍(4s)，播完重新洗牌
         （不连续重复；20s 内五种动作全部出现）
类别页/追问页   无 GIF，静态像素 UI（吉祥物定格帧 + 对话气泡）
思考/摇签页：
  ① thinking         弹性段：最少 1 整遍(4s)，之后每帧(400ms)检查签文
                      是否就绪；就绪（或 10s 超时切兜底）即退出
  ② getting_lottery  固定 2 遍(2.4s) —— 摇签仪式
  ③ lottery_get      1 遍(1.8s) + 末帧定格 0.5s —— 出签悬念
结果页   无 GIF，纯像素排版
```

- 最短动画链 ≈ 8.7s，覆盖 LLM 典型延迟（3~8s），绝大多数情况用户体感零等待。
- **再求一签 → 直接回类别页**（不回待机）；任何超时返回 → 硬切回待机轮播。
- 全程仅一个 `lv_gif` 对象，切段换源，解码画布只占一份。

## 后端接口（core-engine 新增路由）

```
POST /api/fortune/draw
请求: { device_id, category, question, answer }
响应: { lot_no, grade, grade_score(1-5), poem(四句), explanation, advice }
```

- 签级由后端**加权随机先定**：上上 15% / 上 30% / 中 35% / 下 15% / 下下 5%；
  再让 LLM 按已定签级、围绕"类别 + 用户处境"写诗和解签。
- Prompt 要求：白话原创、不用典故成语故事、直接回应用户选择的处境、只用常用字。
- 简单 token 鉴权（专机专用）；LLM 侧超时预算 8s（板端总超时 10s）。

## 网络与兜底

- WiFi 凭据硬编码在配置头文件（专机摆摊场景足够）。
- 兜底签谱：6 类别 × 5 签级，每格预写 1~2 条（约 40 条，AI 批量初稿 + 人工过审），
  存固件；断网/超时时本地按同样权重摇签级后取对应文案，流程与动画完全一致。

## 打印

- 复用现有 worker 线程 + ESC/POS 管线（UTF-8→GBK、双倍字号标题、走纸）。
- 票面：店名头 → 第 X 签·签级 → 诗 → 解签 → 行动建议 → 落款"诚心求签 运随心转"。
- 触发方式：结果页 [打印签文] 按钮，按需打印；打完置灰为"已出票"。
